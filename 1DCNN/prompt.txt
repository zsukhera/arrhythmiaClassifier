## Goal

Replicate:

  M. M. Farag, "A Tiny Matched Filter-Based CNN for Inter-Patient ECG
  Classification and Arrhythmia Detection at the Edge," Sensors, vol. 23,
  no. 3, art. 1365, 2023, doi: 10.3390/s23031365.
  https://www.mdpi.com/1424-8220/23/3/1365

The paper classifies single MIT-BIH heartbeats into AAMI classes using the
de Chazal DS1/DS2 inter-patient split (train on DS1 patients, test on DS2
patients). The model is very small (about 1.3k-1.6k parameters, about 15 KB as
TFLite):

  ECG beat (MLII, 128 Hz, 64 samples, optionally its first derivative)
    -> Conv1D with 13 kernels initialised from class-average "matched filter"
       templates computed on DS1
    -> BatchNormalization -> GlobalMaxPooling1D
    -> concatenated with a small fully-connected stack fed by dynamically
       normalised RR-interval features
    -> Dense softmax output (3, 4 or 5 AAMI classes)

Then EXTEND it (not in the paper) with a binary task: Normal vs Arrhythmia.

Several details are only in the paper's tables, which are images (Tables 1-6).
Before writing code, open the PDF and read Tables 1-4. Wherever the text below
says "ASSUMPTION", implement the stated default, make it configurable in
`configs/default.yaml`, check it against the PDF tables, and list it in the
README.

Cite the paper above in the README and in each module's header comment.

## IMPORTANT: check what "accuracy" means (verify this)

The paper reports "average accuracy". In another paper we replicated
(Yakut 2020), "accuracy" turned out to be the MEAN ONE-VS-REST accuracy,
1 - 2e/K, not plain multiclass accuracy 1 - e. For K = 3,
98.18 % one-vs-rest would be only 97.27 % plain accuracy.
Implement both and report them side by side. Use Table 4's per-class numbers
to check which definition matches, and state the result in the README.
Always report the majority-class ("predict all N") baseline next to accuracy:
N is about 89.5 % of DS2 beats (paper Sec 5.1), so accuracy alone says little.

## Preprocessing (paper Sec 3, 5.2)

- The paper feeds RAW MLII with no filtering during training. Implement a
  `--filter {none, bandpass}` option. Default `none` (paper-faithful). The
  `bandpass` ablation is 0.5-40 Hz 4th-order Butterworth, zero-phase, matching
  our preprocess.py.
- Resample 360 Hz -> 128 Hz with `scipy.signal.resample_poly(x, 16, 45)`.
  Map R-peak indices with round(r * 128 / 360). ASSUMPTION: the paper does not
  say which resampling method it used.
- Segment: 64 samples (0.5 s) centred on the R peak. ASSUMPTION: 32 samples
  before the R peak and 32 after.
- Short/edge beats: "Heartbeat segments with intervals less than 0.5 s are
  edge-padded". ASSUMPTION: if the window would cross the record start or end,
  pad with the edge value (np.pad mode="edge"). Log how many beats were padded.
  Do NOT drop them: the paper keeps all annotated beats.
- Normalisation. ASSUMPTION: subtract the per-segment mean (the paper times a
  "mean" step in MF computation, Sec 5.2). Make `z-score` and `none` options.
- First derivative: np.diff of the normalised segment, then edge-pad to keep
  64 samples. ASSUMPTION about length and edge handling.
- Input variants (`--input`): signal | derivative (default, paper's best) |
  both (2 channels, each with its own MF templates).
- NK=32 variant: keep the central 32 samples (drop 16 from each edge)
  (Sec 5.2).

## RR features (paper Sec 3)

Causal only: use past RR intervals, so the ESP32 can compute them in real time.
- RR intervals come from ALL annotated beats, including beats that will be
  dropped (e.g. F and Q in 3-class mode). That way an interval never jumps
  over a dropped beat.
- pre_RR  = time from the previous beat to this beat.
  post_RR = time from this beat to the next beat. This adds one beat of
  latency on the device, which the paper accepts.
- local_mean  = moving average of the last 80 RR intervals.
  global_mean = moving average of the last 400 RR intervals.
  At the start of a record, average whatever history exists.
- Features (ASSUMPTION: 4 features; the paper says "preceding and subsequent
  RR ... normalized to the local and global RR interval means"):
    pre_RR / local_mean, pre_RR / global_mean,
    post_RR / local_mean, post_RR / global_mean
- Do NOT feed absolute RR values. The paper warns they degrade accuracy.
- Sanity check: train an XGBoost (or LightGBM) classifier on these 4 features
  alone, 3-class. The paper reports about 93 % accuracy and recall
  N/S/V = 97/60/58 %. If you are far off, fix the RR features before moving on.

## Matched-filter templates (paper Sec 4.2, 5.2)

- Compute on DS1-train ONLY. ASSUMPTION: the paper says "DS1". Using only the
  train records avoids leaking the validation records. Run "all of DS1" as an
  ablation.
- One template per MIT-BIH beat sub-class present in DS1-train: the average of
  all preprocessed segments (or derivatives, for the derivative input) of that
  sub-class. The paper uses 13 templates. ASSUMPTION: the 13 are the
  sub-classes N, L, R, e, j, A, a, J, S, V, E, F, Q. Confirm this against
  Table 1 and Figure 4. Log which sub-classes exist and how many beats went
  into each template. If a sub-class has fewer than 5 beats in DS1-train, log
  it and fall back to "all DS1" for that template only.
- Use the same 13 templates for 3-, 4- and 5-class models and for the binary
  model.
- Kernel weight layout: Keras Conv1D kernels have shape (NK, in_channels, 13).
  Put template i in kernel[:, 0, i]. Flip each template in time only if your
  framework convolves rather than correlates. Keras Conv1D is
  cross-correlation, so do NOT flip. Add a unit test that checks this.
- ASSUMPTION: scale each template to unit L2 norm, so that no single class
  dominates GlobalMaxPooling because of amplitude.
- Ablations from the paper: 5 templates (one per AAMI super-class) and
  per-record templates. The paper found both worse than 13.

## Model (paper Sec 4, Figure 3, Table 3; Keras / TensorFlow)

  ecg_in (64 or 32, C)   C = 1 (signal or derivative) or 2 (both)
    Conv1D(filters=13, kernel_size=NK, strides=1, padding="valid",
           use_bias=True, activation="relu")
    BatchNormalization()
    GlobalMaxPooling1D()                         -> 13 values
  rr_in (4,)
    Dense(16, relu) -> Dense(16, relu) -> Dense(16, relu)
  Concatenate -> Dense(n_classes, softmax)

ASSUMPTIONS to check against Table 3: padding="valid"; ReLU (the paper says
"ReLU or Tanh"); the RR stack of 3 x Dense(16). With NK = 64 this gives about
1.6k parameters, inside the paper's stated range of 1267-1619. Print
`model.summary()` and the parameter count for every variant. Fail loudly if a
3-class single-channel model falls outside 1,000-2,000 parameters, and then fix
the RR stack to match Table 3.

Kernel init (`--init`): mf_trainable | mf_frozen (Conv1D trainable=False) |
default (Glorot uniform). NK (`--nk`): 64 | 32.

- Loss: categorical cross-entropy. Adam with learning rate 1e-3.
- LR schedule: ReduceLROnPlateau(monitor="val_loss", factor=0.5, patience=5,

  without details.
- Batch size 512, max 500 epochs, EarlyStopping(monitor="val_loss",

  sklearn `compute_class_weight("balanced")` on DS1-train. ASSUMPTION about
  the formula. The paper's best model (Model 6) used NO class weights, and
  class weights raised minority sensitivity at the cost of precision.

- Run independent configurations in parallel: a process pool sized to CPU
